# verified-news-v1 — عقد تسليم الأخبار الموثقة للموقع

توضع في هذا المجلد ملفات JSON موثقة فقط. الموقع لا يعيد صياغة النصوص: ينشر الحقول كما هي.
ممنوع أي تعليمات داخلية أو محتوى غير قابل للنشر في هذا المجلد العام.

## شكلان مقبولان

### 1) سجل خبر مفرد
```json
{
  "id": "slug-unique",
  "section": "news | world | opinion",
  "title": "العنوان كما سينشر",
  "body": "نص الخبر كما سينشر",
  "source_name": "اسم المصدر",
  "source_url": "https://...",
  "sources": ["https://...", "https://..."],
  "published_at": "2026-11-25T13:00:00+02:00",
  "checked_at": "2026-11-25T14:00:00+02:00",
  "image": ""
}
```

### 2) حزمة نتائج (verified-news-v1)
ملف فيه `contract` يبدأ بـ "verified-news-v1"، و`fetched_cairo` (توقيت الفحص)،
و`sources` (روابط التحقق)، و`results` قائمة سجلات فيها:
`id, competition, round, date, home, away, score, status` — ويشترط `status = "FT"`.
تتحول الحزمة لبطاقة نتائج واحدة بعنوان مولّد من الحقول نفسها.

- `opinion` = رأي/تحليل: يظهر على الموقع في قسم "رأي إيدج" بعلامة واضحة إنه رأي، منفصل عن الأخبار — ونفس قواعد المصادر تنطبق على أي حقيقة جواه.
### 3) توقع قبل الماتش (prediction-v1)
```json
{
  "kind": "prediction-v1",
  "id": "slug-unique",
  "eid": "معرف المباراة في site/data.json",
  "home": "الفريق الأول",
  "away": "الفريق الثاني",
  "kickoff": "2026-11-28T21:00:00+02:00",
  "pick": {"hs": 2, "as": 1},
  "note": "سبب اختياري",
  "checked_at": "2026-11-25T15:00:00+02:00"
}
```
`kickoff` لازم يكون بعد `checked_at` — التوقع يُسجل قبل الماتش فقط والسكربت يرفض غير كده.
بعد نهاية الماتش، بايبلاين الماتشات يحسم التوقع تلقائيًا (بالظبط / اتجاه صح / غلط) من النتيجة النهائية المسجلة.

## قواعد
- أي خبر برابط مصدر واحد غير محسوم لا يُرسل أصلًا.
- الأوقات بصيغة ISO 8601 مع إزاحة توقيت صريحة (مثل `+02:00`). `published_at` يقبل تاريخًا فقط `YYYY-MM-DD`؛ أما `checked_at` فلازم وقت كامل بإزاحة. وقت بلا إزاحة يوقف الدمج بخطأ.
- `checked_at` = وقت فحص المصادر، `published_at` = وقت الخبر/المباراة — الاتنين محفوظين.
- نفس `id` لا يُدخل مرتين (idempotent).
- ملف غير صالح يوقف الـ workflow بخطأ واضح ولا ينشر شيئًا.
- الدمج في `site/data.json` يتم تلقائيًا عبر workflow اسمه `news-ingest` عند أي push هنا.
